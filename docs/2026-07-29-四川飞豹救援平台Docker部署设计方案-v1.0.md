# 四川飞豹救援平台 Docker 部署设计方案

## 一、部署目标

使用 Docker Compose 统一构建并运行官网、管理后台、NestJS 后端和 MySQL，保留现有 `website/`、`admin/`、`backend/` 目录结构。部署配置不得内置数据库密码、JWT 密钥或第三方服务密钥。

## 二、服务范围

| 服务 | 作用 | 对外端口 | 数据持久化 |
|------|------|----------|------------|
| `website` | Nginx 提供官网静态文件并代理公共接口 | `80` | 无 |
| `admin` | Nginx 提供管理后台静态文件并代理管理接口 | `8080` | 无 |
| `backend` | 运行 NestJS API、上传文件和地图代理 | 不直接暴露 | `backend_uploads` |
| `mysql` | 运行 MySQL 8.4 | 不对外暴露 | `mysql_data` |

官网与后台分别使用独立容器和端口，避免修改现有 Vue Router 的根路径。两个 Nginx 容器均将 `/api/`、`/uploads/`、`/_AMapService/` 转发至 `backend:3003`。

## 三、构建与运行

- 官网和后台使用 Node 多阶段构建，最终镜像只保留 Nginx 与静态产物。
- 后端使用 Node 多阶段构建，生产镜像只安装生产依赖，并使用非 root 用户运行。
- MySQL 健康后再启动后端；后端端口可连通后，再启动官网和后台。
- 所有镜像设置重启策略，上传文件和数据库使用命名卷持久化。
- 管理后台端口仅绑定宿主机回环地址，通过外部 HTTPS 网关对外提供服务。

## 四、配置与数据流

根目录 `.env` 由 `.env.example` 复制生成，仅保存在部署服务器。Compose 将数据库连接、域名、JWT、高德地图配置注入后端；前端构建参数通过 Docker build args 注入。

浏览器请求先进入对应 Nginx 容器，静态资源由 Nginx 返回，业务请求通过 Docker 内网转发到后端，后端再通过服务名 `mysql` 访问数据库。

## 五、边界与恢复

- `docker/mysql/init/10-schema.sql` 提供当前 27 张业务表的纯结构初始化，不包含历史业务数据或账号凭证。
- MySQL 初始化目录只在数据卷为空时执行；已有数据升级应使用迁移脚本或人工恢复流程。
- 数据库端口不映射到宿主机，运维连接使用 `docker compose exec mysql mysql`。
- 公开注册默认关闭；初始管理员只能通过一次性环境变量创建，且首次登录必须改密。
- 上线前必须修改数据库密码、Root 密码和 JWT 密钥；占位值不得用于生产。
- 回滚应用镜像不得删除 `mysql_data` 和 `backend_uploads` 卷。
